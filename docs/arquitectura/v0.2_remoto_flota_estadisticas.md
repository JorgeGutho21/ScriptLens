# Arquitectura de la versión 0.2: acceso remoto, varias computadoras, estadísticas y auditoría

## 1. Vista general

```
┌────────────────────────── PC con ScriptLens ───────────────────────────┐
│ Tauri (Rust) ── backend_info ──► Interfaz React                         │
│      │ arranca                       │ fetch + X-ScriptLens-Token        │
│      ▼                               ▼                                   │
│ Motor Python (un proceso) ── API LOCAL 127.0.0.1:<aleatorio> (sin cambios)
│   Engine: SystemSampler (1 s) · ProcessMonitor (2 s) · SQLite            │
│     ├─ StatsService: resume por minuto/hora (no mide de nuevo)           │
│     ├─ FleetService: consulta a otras PC cada 5 s (consola)              │
│     ├─ Audit30State: auditoría de solo lectura bajo demanda              │
│     └─ RemoteService ── API REMOTA HTTPS :8765 (apagada por defecto) ────┼──► celular / laptop / consola
│                         solo IPv4 privadas · solo GET de consulta        │
└──────────────────────────────────────────────────────────────────────────┘
```

Los dos servidores HTTP comparten **el mismo `Engine`**: el acceso remoto y la consola no añaden muestreos de CPU o RAM.

## 2. Acceso remoto (`backend/remote/`)

| Pieza | Decisión |
| --- | --- |
| `service.py` | Estados *apagado → activo ⇄ pausado → apagado*. Un `uvicorn.Server` adicional en un hilo, con un socket por cada IPv4 privada (no `0.0.0.0`). |
| `tls.py` | Certificado ECDSA P-256 autofirmado, generado una vez en la carpeta de datos; la huella SHA-256 se muestra en la PC. |
| `auth.py` | Código de 6 cifras (5 min, un uso) + frase de verificación + aprobación del propietario. Tokens de 256 bits guardados como SHA-256, caducidad (12 h navegador / 30 días consola), revocación individual o total, 5 fallos/min por IP y 20 globales. |
| `app.py` | Aplicación FastAPI independiente con **lista explícita** de rutas (`ALLOWED_ROUTES`). Middleware: IP privada → límite de 240 peticiones/min → ruta permitida → sesión. Cabeceras CSP, `no-store`, `DENY`. |
| `invites.py` | Invitaciones por correo: token de 256 bits guardado como SHA-256, enlace con el token en el **fragmento** (`#invitacion=`, no llega al servidor ni a registros), correo como segunda llave, un solo uso atómico, caducidad, bloqueo tras 3 correos erróneos, 5 fallos/min por IP y permisos por sesión (intersección con lo que comparte la PC). |
| `mailer.py` | Modo local (archivo `.eml`, predeterminado) o SMTP con STARTTLS configurado por variables de entorno; la contraseña nunca se guarda ni se muestra. |
| `views.py` | Datos compartidos sin rutas, PID, usuario ni línea de comandos; cada respuesta lleva `medido_en`. |
| `web/` | Página para celulares sin dependencias externas; inserta datos con `textContent`; marca «Desconectado» o «Datos atrasados» a los 10 s. |

**Amenazas consideradas:** otro equipo de la red (código + aprobación + límite de intentos), suplantación de la PC
(huella; la consola la fija), robo de la cookie (HttpOnly, Secure, SameSite=Strict, nunca en la URL ni en el QR),
escalada a acciones (las rutas no existen en el servidor remoto; prueba que recorre todas las rutas locales),
exposición a Internet (solo IP privadas, sin UPnP ni reenvío de puertos).

## 3. Consola de varias computadoras (`backend/fleet/`)

Patrón *hub → agente* tomado de **Beszel**: la consola consulta a los agentes (no al revés), guarda historial propio y
marca como desconectado al que no responde. Adaptaciones: el agente es el mismo ScriptLens con el acceso remoto
activado (no se instala ningún servicio), la vinculación usa el mismo flujo de aprobación que el celular, la huella TLS
se fija al vincular (TOFU) y el token se cifra con **DPAPI** del usuario de Windows.

## 4. Estadísticas (`backend/stats/`)

Inspirado en **ActivityWatch** (seguimiento local, privado y con consentimiento) y en el historial agregado de
**Beszel**: minuto (7 días) → hora (retención configurable, 90 días por defecto). Inactividad con `GetLastInputInfo`
(solo un contador). Aplicaciones en primer plano: solo nombre del ejecutable y solo con consentimiento. Arranques desde
el registro de eventos (Kernel-General 12/13 y Power-Troubleshooter 1). Dominios web: **no implementado**; requeriría
una extensión voluntaria del navegador.

## 5. Auditoría de 30 controles (`backend/audit30/`)

Recolección PowerShell constante y de solo lectura, evaluación en Python con pruebas por regla. Idea tomada de
**HardeningKitty**: cada control con identificador, valor encontrado, resultado y recomendación, sin aplicar cambios.
De **osquery**, la idea de consultar el estado del sistema como datos estructurados (JSON) en lugar de texto libre.

## 7. Tecnologías implementadas y evaluadas

| Tecnología | Estado | Para qué | Requisitos |
| --- | --- | --- | --- |
| HTTPS con certificado propio (`cryptography`) | Implementado y probado | Cifrar y autenticar el tráfico en la LAN | Ninguno adicional |
| DPAPI de Windows | Implementado y probado | Proteger los tokens de la consola | Windows |
| SQLite (esquema v2) | Implementado y probado | Sesiones, equipos, estadísticas y alertas | ~1–5 MB por mes de uso |
| Ollama + Qwen3 1.7B | Implementado y medido | Modo IA rápida | ~1,6 GB de RAM/VRAM |
| GitHub Actions | Implementado | Pruebas Python (incluida seguridad remota), oxlint, TypeScript, `cargo check`, instalador y Pages | Ejecutores de GitHub |
| Docker Compose / Kubernetes | **Evaluado y descartado** | — | — |

**Kubernetes y Docker.** ScriptLens es una aplicación de escritorio para Windows cuya consola es otra instancia de la
misma aplicación en la LAN. No existe un servicio central que escalar, y empaquetar el motor en un contenedor Linux
impediría leer las API nativas de Windows (procesos, Defender, registro, DPAPI). Por eso no se añadieron manifiestos ni
se afirma que Kubernetes se haya usado.
